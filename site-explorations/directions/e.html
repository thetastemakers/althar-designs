Althar
BriefResearch note

Open-source infrastructure for software engineering with AI agents

Agents come and go. The project stays.

Althar is a home for your project’s memory, and a coordinator that runs agents against it. Any agent, any model, any subscription, on your servers.

The proposition

The agents will keep changing. Your project should not have to.

Every major AI coding company is building a project layer, and each one ties it to the agent it sells. Althar keeps project knowledge open and independent, and uses it to run work across whichever agents are best this month.

01The problem

Agents can now do real engineering work. The way we run them hasn’t caught up.

Problem A

The project has no memory of its own.

What a team knows is spread across instruction files, chat histories and people’s heads. Switch tools and it has to be rebuilt.

  • Every new session starts from a re-typed brief
  • Decisions live in one vendor’s history
  • Nobody can tell a rule from a stale guess

Problem B

The developer is the message bus.

An agent finishes. Someone reads the diff, briefs a reviewer, carries the findings to a fixer, starts the tests and decides what’s next.

  • Parallel agents create parallel queues
  • Every hand-off interrupts real work
  • Findings don’t change the plan on their own

Vendors have little reason to make project memory portable to a competitor. So it has to live in an independent layer, one that any agent can be briefed from.

02The market

Everyone is building this layer, each for their own agent.

For each vendor that’s rational: memory that moves to a competitor stops keeping customers. For the team it’s the wrong trade, because the best coding model has changed hands repeatedly in eighteen months.
